Software Requirements Specification (SRS): Colossians Cleaning Services
1. Objective
The objective of this Software Requirements Specification (SRS) is to define the functional and non-functional requirements for extending the existing web-based CRM portal into a mobile application ecosystem for Customers (Clients) and Staff (Cleaners), while retaining a web-based Admin Portal built using Laravel.
The current system is a web CRM that manages end-to-end cleaning operations, including bookings, job scheduling, staff assignment, payments, reviews, and notifications. While the web portal effectively serves administrative and desktop use cases, there is a strong opportunity to enhance usability, accessibility, and operational efficiency by introducing dedicated mobile applications.
Primary Goals
* Convert the existing web CRM experience into mobile-first applications for:
   * Customers (booking, tracking, reviews, notifications)
   * Staff/Cleaners (job management, check-in/out, availability, payouts)
* Maintain a centralized Admin Web Portal (Laravel-based) for:
   * Operational control
   * Job assignment and monitoring
   * Staff and customer management
   * Payments, reports, and audits
* Ensure real-time synchronization between web and mobile platforms using shared APIs
* Improve user experience, response time, and on-the-go accessibility without changing core business workflows

3. Proposed System Architecture
3.1 Architecture Overview
The platform will use a centralized, API-driven architecture with:
* One backend system (Laravel)
* One mobile application for both Clients and Cleaners
* One web-based Admin Portal
Instead of building two separate mobile applications, a single mobile app will be developed, and users will select their role (Client or Cleaner) during onboarding or login.
This approach:
* Reduces development and maintenance cost
* Ensures consistent user experience
* Allows easy role switching (if approved)
* Keeps all business logic centralized
3.2 High-Level System Components
1. Backend System (Central Platform)
Technology: Laravel (Web + REST APIs)
The Laravel backend will act as the single source of truth for the entire ecosystem.
Responsibilities:
* User authentication and role assignment
* Role-based access control (Admin / Client / Cleaner)
* Job lifecycle management
* Scheduling and conflict detection
* Payments and payouts calculation
* Notifications (email, SMS, in-app)
* Compliance, audit logs, and security rules
The backend exposes secure APIs consumed by the mobile app.
2. Admin Web Portal
Platform: Web (Laravel)
Used only by system administrators.
Functions:
* Manage jobs, schedules, and assignments
* Approve and monitor cleaners
* Manage customers and properties
* Review documents, eligibility, and training
* Monitor job execution and payouts
* Generate reports and audit logs
Admins do not use the mobile app.
3. Single Mobile Application (Client + Cleaner)
Platform: Mobile App (Android & iOS – cross-platform)
This is one application, shared by both user types.
Role Selection Flow
* On first launch or registration, user selects:
   * I am a Client
   * I am a Cleaner
* Based on the selected role:
   * Relevant onboarding flow is shown
   * Only role-specific features are enabled
* Backend rules enforce role permissions
A user can never access features outside their assigned role.
3.3 Mobile App – Role-Based Experience
Client Role (within same app)
After login as Client, the app displays:
* Client dashboard
* Property management
* Job creation and calendar
* Job tracking and notifications
* Preferred staff and profile management
Cleaner Role (within same app)
After login as Cleaner, the app displays:
* Cleaner dashboard
* Job assignments and acceptance
* Check-in / check-out
* Availability management
* Work hours and payment view
* Training, documents, and reviews
Each role has:
* Separate navigation
* Separate permissions
* Separate workflows
But shares:
* Same app binary
* Same backend
* Same notification system
3.4 Authentication & Role Management
* Single authentication system
* Role stored at backend level
* Token-based authentication for mobile app
* Role checked on every API request
* Backend decides:
   * What data is accessible
   * What actions are allowed
This prevents role misuse or privilege escalation.
3.5 Data Synchronization & Real-Time Updates
* All data is stored in one centralized database
* Actions by one role reflect instantly across others:
   * Client creates job → Admin sees it
   * Admin assigns cleaner → Cleaner receives notification
   * Cleaner checks out → Client sees job completed
No duplication or manual syncing required.
3.6 Advantages of Single Mobile App Approach
* Lower development cost than two separate apps
* Faster deployment and updates
* Unified notification and authentication system
* Easier future enhancements
* Reduced app store management overhead
3.7 Architecture Summary (Simplified)
* Laravel Backend → Core business logic & APIs
* Admin Web Portal → Full operational control
* Single Mobile App → Client & Cleaner access via role selection
* Role-Based UI & APIs → Secure and isolated experiences
* Central Database → Real-time consistenc

2. Calendar Module (Admin Scheduling System)
The Calendar Module is the core operational dashboard used by administrators to plan, monitor, and control all cleaning jobs across clients, cleaners, properties, and dates.
It provides a calendar-based view of all jobs, supports advanced filtering, and allows full job lifecycle management directly from the calendar.
2.1 Calendar Views
The admin can switch between multiple calendar views depending on planning needs:
         * Daily View
         * Hour-by-hour breakdown of jobs
         * Useful for same-day conflict resolution and urgent scheduling
         * Weekly View
         * Cleaner workload distribution across the week
         * Helps balance assignments and availability
         * Monthly View (Default)
         * High-level overview of all jobs
         * Displays multiple jobs per day with “+ more” expansion
2.2 Calendar Header & Filters
At the top of the calendar, the admin has real-time filtering controls to narrow down jobs:
Filters Available
         * Client Name – Select a specific client
         * Cleaner Name – View jobs assigned to a specific cleaner
         * Property Name – Filter by service location
         * Job Status – All / Created / Pending / Approved / In Process / Finished / Cancelled
         * Month & Year Selector – Navigate between months (e.g., January 2026)
These filters update the calendar dynamically without page reload.
2.3 Job Display on Calendar (Monthly View)
Each calendar date displays multiple job cards. If jobs exceed visible space, a “+X more” indicator appears.
Each Job Card Displays:
         * Client Name
         * Service Time Slot
         * Start time – End time (e.g., 🕒 08:00 – 10:30)
         * Cleaner Name
         * Or “Cleaner yet to be assigned”
         * Property Address
         * Job Status
         * Visually distinguishable (e.g., Finished, Approved, Pending, In Process)
Status-Based Visual Indicators
         * Jobs are color-coded by status to allow instant recognition:
         * Created
         * Pending
         * Approved
         * In Process
         * Finished
         * Cancelled
2.4 Job Status Lifecycle
Jobs move through a clearly defined lifecycle:
         1. Created
         * Job created but cleaner not assigned
         2. Pending
         * Awaiting approval or confirmation
         3. Approved
         * Confirmed and scheduled
         4. In Process
         * Cleaner has started the job
         5. Finished
         * Job completed successfully
         6. Cancelled
         * Job cancelled by admin or system
Each status change is logged and reflected instantly on the calendar.
2.5 Job Detail View (On Click)
When the admin clicks on any job in the calendar, a Job Detail Panel / Page opens.
Job Detail Information Includes:
Basic Information
         * Client Name
         * Property Name & Full Address
         * Job Date
         * Start Time & End Time
         * Total Duration
Assignment Details
         * Assigned Cleaner(s)
         * Supports single or multiple cleaners
         * Cleaner availability status
         * Option to assign / reassign cleaner
Job Status Controls
         * Change job status (Created → Pending → Approved → etc.)
         * Cancel job with reason
         * Mark job as completed (manual override if needed)
Operational Notes
         * Internal admin notes
         * Cleaner notes (if applicable)
2.6 Admin Actions from Calendar
Directly from the calendar or job detail view, admin can:
         * Create a new job on any selected date
         * Assign or change cleaner(s)
         * Modify job time slots
         * Cancel or reschedule jobs
         * View full job history
         * Resolve scheduling conflicts
2.7 Cleaner Availability & Workload Visibility
The system displays cleaner availability blocks directly within the scheduling logic.
Admin can see:
         * Cleaner working hours
         * Unavailable days
         * Existing job assignments
         * Daily workload per cleaner
This ensures realistic and fair scheduling.
2.8 Conflict Detection & Validation (Critical Logic)
The system automatically validates scheduling actions and prevents conflicts.
System Warnings Triggered When:
         * A cleaner is double-booked for overlapping times
         * A cleaner exceeds maximum daily working hours
         * A job overlaps another job for the same cleaner
         * A cleaner is marked unavailable on that date
Admin receives:
         * Immediate visual warnings
         * Clear error messages explaining the conflict
         * Option to adjust time or cleaner before saving

4. Scheduled Jobs (Recurring Job Management)
The Scheduled Jobs module is used when a customer requires recurring cleaning services (weekly, bi-weekly, or custom schedules).
Instead of creating individual jobs manually each time, the system manages them using recurrence rules (RRULE) and automatically generates future jobs.
4.1 Purpose of Scheduled Jobs
This module allows Admin to:
         * Manage long-term recurring clients
         * Automatically generate future jobs
         * Assign fixed or rotating cleaners
         * Pause or resume services when required
         * Maintain consistency for commercial and residential clients
Typical use cases:
         * Weekly office cleaning
         * Bi-weekly residential cleaning
         * Multi-day recurring commercial contracts
4.2 Scheduled Jobs Listing (Admin View)
This screen shows all recurring job templates, not individual daily jobs.
Search & Filters
Admin can search scheduled jobs using:
         * Property name
         * Client name
         * Cleaner name
         * Job type (Residential / Commercial)
         * Active / Inactive status
Scheduled Jobs Table Fields
Each row represents one recurring job configuration.
Client & Property
         * Client name
         * Property name
         * Full address
         * Postal code
Scheduling & Frequency
         * Frequency
         * Weekly
         * Every 2 weeks
         * Custom recurrence
         * RRULE description
         * e.g. “Every single week on Tuesday”
         * Start date
         * End date (optional)
         * Next job date (auto-calculated)
         * Occurrence count (if limited)
Time & Assignment
         * Start time
         * End time
         * Assigned cleaner(s)
         * Copy cleaners option (reuse same cleaners across occurrences)
Job Classification
         * Job type (Residential / Commercial)
         * Cleaning category
Status & Control
         * Active (true / false)
         * Inactive start date
         * Inactive end date
         * Is deleted (soft delete)
4.3 Creating a Recurring Job (Scheduling Flow)
When a customer requests recurring cleaning:
Step 1: Create Base Job
Admin creates a job using Add Job flow:
         * Client & property selected
         * Cleaning type defined
         * Equipment & access preferences set
         * Preferred cleaner assigned (optional)
Step 2: Enable Recurrence
Admin selects:
         * Frequency (weekly / bi-weekly / custom)
         * Days of week (e.g. Monday, Wednesday)
         * Start date
         * Optional end date or number of occurrences
System generates an RRULE internally.
Step 3: Assign Cleaners
Admin can:
         * Assign fixed cleaner(s) for all occurrences
         * Assign multiple cleaners
         * Allow future reassignment if neede
4.4 Automatic Job Generation Logic
The system will:
         * Calculate next job date
         * Auto-create individual jobs based on RRULE
         * Maintain link between scheduled job and generated jobs
         * Prevent overlaps or double booking
         * Respect cleaner availability and daily limits
Each generated job:
         * Appears in Jobs table
         * Appears in Calendar
         * Inherits all base settings
         * Can still be edited individually if required

Resume Job

                  * Preferred staff appear at the top of staff lists when creating a job.
                  * If a customer previously booked a cleaner, that cleaner is automatically suggested for future jobs.
                  2. Work Shifts Display:
                  * For each staff, display daily work shifts (start and end times) and weekly schedule.
                  * Only future available slots are shown for booking; past or fully booked slots are hidden.
                  3. Slot Selection for Jobs:
                  * Customers pick a time slot from the available hours of preferred staff.
                  * Once selected, the job can be created and automatically assigned to that staff member if available.
                  * Multiple slots per staff can be shown for flexibility.
                  4. Availability Status:
                  * Indicate available, partially available, or no slots available for each staff.
                  * Slots already assigned to other jobs are disabled to prevent double booking.
                  5. Priority Assignment:
                  * If a customer marks staff as preferred and creates a job:
                  1. Preferred staff are automatically suggested first for assignment.
                  2. Customers can manually assign any preferred staff based on availability.
                  3. Non-preferred staff can still be assigned if preferred staff are unavailable.
                  6. Dynamic Updates:
                  * Staff availability updates in real-time as other jobs are assigned or canceled.
                  * Any changes in work shifts reflect immediately on the customer’s booking screen.

End-to-End Platform Flow
(Client → Cleaner → Admin → Job Completion)
1. CLIENT (CUSTOMER) – COMPLETE FLOW
1.1 Client Registration & Secure Access
                  * Sign-up: Client registers via mobile app or web portal using email or phone number with a secure password.
                  * Verification: OTP verification (SMS/email) is mandatory to confirm authenticity.
                  * Role-Based Authentication: Ensures client cannot log in as a cleaner or admin.
                  * Post-Login: After verification, the client lands on the Client Dashboard, showing:
                  * Profile completion percentage
                  * Quick action buttons for creating jobs, viewing properties, and preferred staff selection
1.2 Property Setup (Residential / Commercial)
Before booking a job, the client must add at least one property.
Property Details Captured:
                  * Property Name
                  * Full Address (Street, City, Postal Code)
                  * Access Instructions (e.g., keys provided, client opens property)
                  * Property Type: Residential / Commercial
                  * Subtype / Additional Details: Number of bedrooms, bathrooms, guest toilets, living rooms, office, dining room, conservatory
                  * Equipment Available: Hoover, washing machine, dryer, cleaning products
                  * Staff Preference: Male / Female / No Preference
                  * Animal Presence: Yes / No
System Behavior Based on Property Type:
                  * Determines payment routing (residential vs commercial)
                  * Sets cleaner payout source
                  * Controls reporting, invoices, and analytics
1.3 Job Creation (Core Workflow Start)
The client initiates the workflow by creating a job:
Steps for Job Creation:
                  1. Select Property
                  2. Choose Job Type (Residential / Commercial)
                  3. Select Date & Start Time
                  4. Enter Expected Duration
                  5. Add Job Instructions / Special Notes
                  6. Select Number of Cleaners Required
                  7. Submit Job
System Behavior After Job Creation:
                  * Job status = Pending
                  * Job appears on:
                  * Client calendar (Day / Week / Month view)
                  * Admin dashboard
                  * Client receives confirmation email
                  * Only available & active cleaners receive job notification emails
1.4 Job Visibility & Client Controls
                  * Client can track jobs in calendar view or list view.
                  * Editing rules: Jobs editable up to 24 hours before start.
                  * Cancellations: Trigger warnings and may restrict future bookings.
                  * Notifications Sent To Client:
                  * Job Created
                  * Job Assigned
                  * Job Accepted
                  * Job Completed
Client Role Ends Here:
                  * Cannot assign cleaners
                  * Cannot approve cleaners
                  * Only tracks job status and receives real-time updates

2.1 Cleaner Onboarding & Eligibility
To join the platform, cleaner must complete:
                  * Registration + OTP verification
                  * Government ID verification / Share Code / NIN
                  * Document uploads (passport, DBS, other compliance)
                  * References & background checks
                  * Availability setup (time slots)
System Restriction: Only active and eligible cleaners receive jobs.
2.2 Job Notification & Interest (Apply Job Flow)
When a client creates a job:
                  1. System checks cleaner availability & eligibility.
                  2. Only active, available cleaners receive email notifications.
Notification Includes:
                  * Property location & type
                  * Job date & time
                  * Duration
                  * Button: “Request to allocate this job”
Cleaner Action:
                  * Click to show interest → Job marked as Requested in Admin Panel
2.3 Job Assignment (Admin-Controlled)
                  * Cleaners cannot self-assign jobs.
                  * Admin assigns cleaners based on:
                  * Availability
                  * Job duration
                  * Staff preference (if specified)
                  * After assignment:
                  * Job appears in Cleaner My Jobs dashboard
                  * Status = Assigned
                  * Cleaner receives assignment notification

                  * Cleaner reviews job details:
                  * Property details, access instructions, and equipment
                  * Client information
                  * Date, time, and special instructions
                  * Cleaner Accepts Job
                  * Status = Accepted
                  * Email sent to client and admin confirming acceptance
2.5 Pre-Job Notifications & Reminders
                  * Cleaner receives automated reminders:
                  * 24 hours before job
                  * 3 hours before job
                  * Cleaner dashboard popups display:
                  * Today’s jobs only
                  * Only accepted jobs
2.6 Check-In / Check-Out (Time Tracking)
                  * Check-In: Allowed at job start or 15 minutes before
                  * Check-Out: At job end or after completion
                  * System Behavior:
                  * Future jobs are locked until their date
                  * Only today’s job accessible
                  * Check-in/out timestamps support overnight and midnight shifts
2.7 Job Completion
                  * After check-out:
                  * Job status = Completed
                  * Hours automatically logged
                  * Cleaner cannot edit or delete job
                  * Feedback request email sent to client
2.8 Cleaner Payment & Records
                  * Hours & pay calculated based on:
                  * Job type (Residential / Commercial)

                  * Daily / weekly / monthly hours
